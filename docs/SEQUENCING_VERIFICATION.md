# Sequencing verification (acceptance branch; not deployed)

The verification service never redesigns primers, updates physical inventory, or writes the primer production database. Frozen project maps and original sequencing archives remain read-only. The development worktree is not a production deployment.

## Modules and entrypoints

- `verification_reference.py`: immutable reference sequence/hash, exact GenBank features, assembly provenance, explicit insert/junction coordinates, CDS, linker, tag, native/fusion stop and additional required elements. `reference_from_canonical` consumes the shared service result. `recover_reference` requires original vector and mapped arms and validates the **entire** assembled sequence; CDS features alone never define insert boundaries.
- `verification_catalog.py`: read-only registered project map discovery. A map enters the selectable catalog only after exact original-backbone assembly validation. Name/identity conflicts are reported, not replaced by fuzzy matching.
- `verification_import.py`: bounded in-memory CWBIO ZIP/FASTA/BAM/TSV/AB1 parsing; no extraction. Event IDs use member content hashes, not sample names. Repackaging and duplicate downloads deduplicate; different batches remain separate. Clone/physical-colony identity stays unknown until explicitly recorded. Generated AB1 is never independent raw quality.
- `verification_align.py`: forward/reverse, circular-aware independent alignment to the design reference; per-region QC and separate target/whole-plasmid statuses. Vendor self-consensus BAM is read-support/heterogeneity evidence only.
- `verification_ui.py`: upload, explicit reference confirmation, additional required feature selection, event/colony history, regional QC and downloads. Changed assignments invalidate stale results. Skipped/unassigned events are not silently certified.
- `verification_store.py`: separate per-user ledger, immutable reference snapshots and policy-versioned run evidence. Default `$HOME/.primer-verification/<user_id>/verification.sqlite3`, configurable via `VERIFICATION_STATE_DIR`; never use `app.db`. Saving/loading is explicit, not performed on import.
- `verification_export.py`: project Excel and self-contained HTML; per-event feature-preserving GBK, reference/consensus FASTA, alignment coordinates, differences, snapshot and QC JSON. Exports and ledger contain private sequences: keep them outside Git.

## Status policy v2 (pre-release blocker corrections)

TSV coordinates are 0-based half-open, with circular reference coordinates modulo the reference length; unwrapped reference alignment coordinates are exported too. Query `query_start0/end0` always refer to the original FASTA interval; `query_oriented_start0/end0` refer to the aligned strand. Reverse-view query coordinates decrease. The HTML base view uses 1-based original reference/query coordinates and displays both actual sequences, gaps, feature labels and highlighted differences. Difference contexts show 20 returned alignment columns on either side; the complete returned alignment is expandable. Homopolymer runs display explicit reference/query lengths. Repeated or long gaps are not unique breakpoint claims. Junctions require 18 reference bases on each side. The full design insert (including non-CDS), required junctions, fusion components and selected elements must be covered and agree. Missing required coverage or ambiguous consensus bases cannot pass. Default minimum support is depth 5 with both read orientations represented at each required position in the returned BAM. These are explicit conservative software defaults, not a platform-calibrated universal quality threshold.

- PASS: all mandatory target regions supported and identical; no unresolved mixture, backbone difference or identity ambiguity.
- FAIL: supported required-region sequence disagreement against an explicitly confirmed expected design reference. A consensus deletion additionally requires 8 exactly matching, mapped reference bases on each side, contiguous original-query anchors, adequate per-base depth/directions and at least 3 unique actual BAM read names whose aligned sequence spans both anchors exactly, including both directions. No read evidence, one-direction evidence or low depth remains INCOMPLETE, never a confirmed deletion based on an empty `all()`. These names do not establish independent molecules. Legacy saved events without decoded BAM blocks need reimport for this evidence. Unsupported terminal overhangs cannot establish a critical insertion. A FAIL identifies disagreement with the confirmed expected design; it does not establish actual sample identity or laboratory root cause.
- REVIEW: retained vendor variants or a BAM deletion subpopulation (>=3 unique read names, >=5% apparent local depth; short deletions included), unresolved reference identity or noncritical retained-backbone differences. Mixture REVIEW can coexist with an INCOMPLETE region; the report preserves both.
- INCOMPLETE: images only, insufficient support, partial required coverage, or no usable sequence.

The BAM deletion threshold does not establish independent molecules or true allele frequency. All unfiltered vendor candidates remain in the evidence export; candidates at >=5% with >=3 alternate records conservatively require REVIEW even when the company filtered them out (including strand-bias candidates). These counts do not establish independent molecules or confirmed mutations. Single-strand/homopolymer candidates need review in context. Generated Q50 AB1 does not satisfy read support. Whole-plasmid status is separate and cannot pass on an insert-only result. Reference assignment remains unconfirmed by default and requires explicit review; candidate names or shared k-mers alone never grant PASS. Reused sample suffixes never establish the same physical colony. `reference_assignment_confirmed`, `expected_design_status` / `expected_design_mismatch_confirmed`, and `actual_sample_identity_status` are separate fields; the last remains NOT_ESTABLISHED. Unconfirmed assignments remain REVIEW regardless of the conditional design comparison. The version and deletion evidence policy participate in the policy hash.

## Existing sequencing-order exports

The shared `sequencing_export.py` remains the formatter. Contract Project keeps its canonical ZIP and adds a standalone workbook download. Design Batch/History adapters use existing successful design rows and actual maps; they do not invoke the primer engine. Confirm species, canonical identity/locus and map resistance. Rice numbered identities are checked against the existing registry. New orders require a confirmed 18-bp arm; historical 21-bp arms are blocked for review rather than truncated. Default three colonies, canonical minimal-backbone names, template validations and the existing 1499-bp cap remain unchanged. Antibiotic choices are read from the original workbook Antibiotic named range. Only explicit AmpR/ampicillin and KanR/kanamycin aliases may normalize to the corresponding allowed official Chinese value; if that target value is absent, export is blocked. The exporter reopens the result and checks actual G-column values and Antibiotic validation coverage, extending that original validation for extra rows. The UI uses those same template options. Contract ZIP and standalone Excel persist in user-scoped session state after rerun, keyed by the exact three uploaded file contents; changed uploads invalidate both. Existing private verification history supports batch, construct and colony ID/suffix filters.

## SnapGene capability boundary

GBK reference maps retain formal features. FASTA plus alignment coordinates/differences enable review and later Desktop comparison. There is **no native SnapGene alignment writer** and no `.dna` alignment claim. Existing optional `.dna` map conversion remains distinct and requires a verified licensed Desktop CLI. A future native alignment exporter needs real SnapGene round-trip acceptance.

## Validation and privacy

Run `PYTHONPATH=app python -B -m unittest discover -s test`. Public tests use synthetic fixtures and existing repository assets. Private real-data acceptance is run only on the laboratory server; archives, sample lists, result reports and private-ledger files must not be staged. Browser rendering of a copied standalone HTML file checks isolation. Streamlit AppTest can test the page without running the production app. Source/database/map hashes must remain unchanged.

## Known technical limits

The in-memory aligner is bounded to 35 million reference/query cells and ZIP input to 40 MB with 150 MB expansion; larger data must use a separately reviewed worker. BAM support is based on the returned trimmed consensus coordinates, not full raw-molecule validation. Mismatched inserts can have nonunique gap placement: inspect matching evidence and do not interpret every alignment gap as a uniquely localized mutation. References with unresolved provenance or origin-crossing insert boundaries require explicit provenance and cannot be automatically frozen. Physical clone/resequencing relationships require experimental records. Persistence requires a private writable state directory and is independent of the primer database.

## Installation and private resources

Install the software as described in README.md. The application and synthetic tests run without laboratory data. Configure an external private resource JSON before launch to load your own authoritative projects, backbone presets, identities and original provider workbooks. No real reference map or sequencing archive is distributed. Generic bundled workbooks are examples; configure the original provider workbook for formal submission.

## Validation

The public synthetic suite and canonical end-to-end smoke test require no private assets. Existing scientific regression assertions are also run privately against the released code with explicit external configuration. Private reports, reference snapshots, alignments and ledgers are not publication artifacts. Native SnapGene alignment is not implemented or certified.
